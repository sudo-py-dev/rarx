# 7z

Implemented in `crates/rarx-formats/src/sevenz/` (`header.rs` database parser,
`coders.rs` coder graph, `mod.rs` reader). Spec: `7zFormat.txt` from the LZMA SDK.

- Start header CRC and next-header CRC are verified; header and pack ranges must lie
  inside the file (truncation is reported as such).
- `kEncodedHeader` is decoded (up to 4 nested levels, 1 GiB cap) and its folder CRC
  checked. An AES-encrypted header needs the password at open time: without one the
  archive reports "encrypted", and a header that fails to decode or match its CRC
  under the given key reports "wrong password".
- Folders are arbitrary coder graphs: bind pairs, multiple pack streams, and
  multi-input coders (BCJ2) are resolved recursively from the unbound output. Pack
  streams are read through one shared file handle (`Arc<Mutex<…>>`) with per-stream
  positions and 64 KiB buffers.
- Coders: Copy, LZMA, LZMA2, Delta, BCJ x86/ARM/ARMT/ARM64/PPC/SPARC/IA64/RISCV, BCJ2
  (via `lzma-rust2`), Deflate (via `flate2`), BZip2, Zstd, PPMd H (`ppmd-rust`; models
  above 2 GiB are refused), 7zAES (`rarx-crypto`). Deflate64 and others are named in
  listings and reported as unsupported.
- 7zAES: AES-256-CBC; key = SHA-256 over `2^NumCyclesPower` rounds of salt ‖
  UTF-16LE password ‖ 64-bit counter (exponents above 24 are refused, `0x3F` means the
  raw salt ‖ password). Derived keys are cached per (salt, exponent). A wrong key
  surfaces as a decode error or CRC mismatch, which extraction reports as
  "wrong password" for encrypted items.
- LZMA dictionaries are allocated at `min(declared, output size)`, never larger than
  the data being decoded.
- Solid blocks: the folder decoder is cached between `open_entry` calls; reading items
  in order decodes each block once, going backwards restarts it, and a partly read
  item invalidates the cache.
- File records: names (UTF-16LE, `\` normalised to `/`), empty-stream/empty-file/anti
  bits (anti items are hidden), M/C/A times, Windows attributes with the
  `0x8000` Unix extension (high 16 bits = `st_mode`, used for symlinks and permissions).
- Listing mirrors 7-Zip: coder labels such as `LZMA2:24 BCJ`, packed size shown on the
  first item of each block.

## Writing

`crates/rarx-formats/src/sevenz/writer.rs`, driven by `rarx-core/src/update.rs`.

- Level 0 → Copy coder; 1–9 → LZMA2 with the `lzma-rust2` preset of that number
  (dictionary encoded as the smallest LZMA2 property code that covers it).
- Solid (default): one folder for all streamed items; `-ms=off`: one folder per file.
- Header: written plain (`-mhc=off`) or LZMA-compressed (1 MiB dictionary) inside a
  `kEncodedHeader` with the folder CRC.
- Items with data are listed first (in stream order), then empty files and folders, as
  7-Zip does; `sevenz-rust2` mis-extracts solid blocks otherwise.
- Records: UTF-16 names, mtime as FILETIME, Windows attributes with the `0x8000` Unix
  extension carrying `st_mode` (permissions, symlinks), per-file CRC-32 in SubStreams.
- Updating or deleting re-encodes kept items (they share solid blocks); the result is
  written to a temp file and renamed into place.
- Encryption (`-p`): each folder becomes LZMA2 (or nothing, at level 0) fed by a 7zAES
  coder with its own random 16-byte IV, no salt and `NumCyclesPower` 19, like 7-Zip;
  the key is derived once per archive. `-mhe` encrypts the LZMA-compressed header the
  same way (and forces header compression). Deleting from or updating an encrypted
  archive re-encodes with the same password and keeps header encryption.
- Cross-checked: every mode, encrypted ones included, extracts byte-identically with
  `sevenz-rust2` (`corpus/7z/sevenz-verify.rs`, password as third argument).

Not yet (writing): multithreaded LZMA2, BCJ/BCJ2 filters for executables, copying
untouched solid blocks without re-encoding, ctime/atime, solid block size limits.

Not yet (reading): Deflate64/Brotli/LZ4 coders, SFX (signature not at offset 0),
multi-volume `.7z.001`, a configurable memory limit (declared output size can still
force a large dictionary allocation).
